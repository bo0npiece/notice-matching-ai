    ## 2. 문제 정의
    
    - **대상 사용자**: 대학생, 사회초년생 (2순위: 유학생, 취약계층 청년)
    - **문제**: 청년 정책·장학금·공모전이 너무 많고 공고가 길고 복잡해서, 받을 수 있는 혜택을 몰라서 놓침
    - **기존 해결책의 한계**
        - 정부 포털·학교 공지는 검색어를 정확히 알아야 찾을 수 있음
        - 자격 조건(나이, 소득, 거주지, 학년 등)을 일일이 읽고 내가 해당되는지 직접 판단해야 함
        - 일반 챗봇은 최신 공고를 모르고 환각 위험이 있음
    - **해결**: 공고를 미리 구조화 + 내 프로필과 자동 대조 + 근거(공고 원문) 제시
    
    ## 3. 핵심 기능
    
    ### ① 프로필 입력
    
    - 나이, 학교·학년, 학과, 거주지, 관심 분야 등을 간단한 폼으로 입력
    - 자연어 입력도 가능: "용인 사는 22살 AI학과 3학년, 자취 중" → AI가 프로필 필드로 자동 변환
    
    ### ② 맞춤 공고 추천
    
    - 나에게 해당되는 공고 목록 + 적합도 점수
    - 카드마다: 혜택 요약, 마감일 D-day, 필요 서류 개수
    
    ### ③ "왜 해당되나요?" 근거 설명 (차별점 핵심)
    
    - 조건별로 ✅ 충족 / ❌ 미충족 / ❓ 확인 필요 표시
    - 각 판단 옆에 공고 원문 출처(문서명, 해당 문단) 표시
    - 예: "만 19~34세 ✅ (공고 2항)", "소득 기준 ❓ → 건강보험료 확인 필요"
    
    ### ④ 질문하기
    
    - "이 장학금이랑 국가장학금 중복 돼?" → 공고 원문 근거로 답변
    
    ### ⑤ 마감 관리
    
    - 관심 공고 저장 → 마감일 타임라인 + 필요 서류 체크리스트
    
    ## 4. HyperCLOVA X API 구성
    
    | API / 모델 | 역할 |
    | --- | --- |
    | 일괄 생성 (스튜디오) | 사전에 공고 수십 개를 한 번에 구조화 |
    | 문단 나누기 | 공고를 조건·혜택·서류 등 의미 단위로 분할 |
    | Structured Outputs | 공고 → {대상, 자격조건[], 혜택, 서류[], 마감일} JSON / 자연어 프로필 → JSON |
    | 임베딩 | 공고 청크 벡터화 → 프로필과 의미 기반 검색 |
    | 리랭커 | 검색 결과 중 진짜 관련 있는 공고만 재정렬 |
    | RAG Reasoning | 조건 충족 여부 판단 + 출처 포함 설명 |
    | HCX-005 (비전) | 사용자가 올린 공고 캡처·포스터 읽기 |
    | 요약 | 긴 공고 → 카드용 3줄 요약 |
    | 라우터 | 요청 분기: 추천 / 질문 / 공고 추가 |
    | 토큰 계산기 | 호출별 사용량 로깅 → 크레딧 근거 자료 |
    
    ## 5. 시스템 흐름
    
    [사전 준비 — 대회 중 1회]
    공고 PDF·웹 텍스트 수집
    → 문단 나누기 → Structured Outputs(조건 JSON)
    → 임베딩 → JSON 파일로 캐싱
    
    [사용자 요청]
    프로필 입력 → (자연어면) JSON 변환
    → 임베딩 검색 Top 20 → 리랭커 Top 5
    → 조건 JSON과 프로필 1차 규칙 비교 (나이·지역 등 코드로 확실하게)
    → RAG Reasoning으로 애매한 조건 판단 + 근거 설명
    → 추천 카드 + 조건별 ✅❌❓ + 출처

    ## 7. 시연 시나리오 (3분)
    
    1. 문제 제시: 공고 사이트 화면 → "이 중 내가 받을 수 있는 건?"
    2. 자연어로 프로필 입력 → 프로필 카드로 자동 정리
    3. 맞춤 공고 5개 추천 → 하나 클릭 → 조건별 ✅❌❓ + 공고 원문 출처
    4. "국가장학금이랑 중복 돼?" 질문 → 근거 기반 답변
    5. 관심 공고 저장 → 마감 타임라인
    6. (보너스) 새 공고 포스터 캡처 업로드 → 즉시 구조화되어 추천에 반영
    
    ## 8. 리스크 & 대응
    
    - **공고 데이터 확보** → 주제 공개 직후 데이터 담당 1명 지정, 공개 공고 20~30개면 충분
    - **잘못된 자격 판단** → 나이·지역 등 명확한 조건은 코드로 판단, AI는 애매한 조건만. "확인 필요(❓)" 상태를 둬서 단정 피하기
    - **환각** → "공고에 없는 내용은 모른다고 답할 것" 프롬프트, temperature 0.1~0.3
    - **"그냥 검색이랑 뭐가 달라?"** → 조건별 판단 + 근거 제시가 핵심 차별점임을 강조
    - **크레딧** → 공고 구조화·임베딩은 1회만 하고 파일로 캐싱
